# ⚡ AI-Powered Smart Energy Consumption Predictor
نظام للتنبؤ باستهلاك الكهرباء: المستخدم يدخل بيانات الاستهلاك السابقة، والنظام يحلّلها ويتوقع الاستهلاك القادم وينبّه عند أي ارتفاع غير معتاد.

## المميزات (مطابقة لمتطلبات المشروع)
| المطلوب | المنفّذ | مكانه |
|---|---|---|
| حساب الاستهلاك السابق | الإجمالي، المتوسط، أعلى/أقل شهر، التغير السنوي | `ml.analyze` → `stats` |
| رسم بياني للاستهلاك | خط زمني + النموذج + التوقع + نطاق الثقة (Chart.js) | `templates/index.html` |
| توقع الاستهلاك القادم | 1 إلى 12 شهرًا مع حد أدنى/أعلى | `ml.analyze` → `forecast` |
| مقارنة الشهور | عن الشهر السابق، عن نفس الشهر في السنة الماضية، ورسم أعمدة لكل سنة | `monthly` + `by_year` |
| اكتشاف الارتفاع غير المعتاد | Robust Z-score على بواقي النموذج + حد أدنى 15% زيادة | `ml.analyze` → `anomalies` |
| اقتراح طرق التقليل | نصائح مرتبة حسب نتائج التحليل (شذوذ، اتجاه تصاعدي، الصيف) | `ml.suggest_tips` |
| نظام تنبيه | تنبيه في الواجهة + حفظ في MySQL + بريد إلكتروني اختياري | `app.sync_alerts` |

## التقنيات
Python • Pandas • Scikit-learn • Flask • SQLAlchemy • MySQL • Docker (جاهز للنشر السحابي)

## طريقة عمل النموذج
1. القراءات (يومية أو شهرية) تُجمَّع إلى استهلاك شهري، والشهور الناقصة تُقدَّر بالاستيفاء الخطي.
2. **Ridge Regression** على: اتجاه زمني + موسمية شهرية (Fourier harmonics). عدد الـ harmonics يتحدد حسب حجم البيانات (أقل من 12 شهر: اتجاه فقط، 12–23: واحد، 24 فأكثر: اثنين).
3. **اكتشاف الشذوذ**: يُدرَّب النموذج مرتين. في الأولى نحسب Robust Z-score (باستخدام MAD) للبواقي ونستبعد الشهور الشاذة، وفي الثانية يُعاد التدريب بدونها حتى لا تفسد الشذوذات التوقع. الشهر يُعتبر ارتفاعًا غير معتاد لو Z ≥ 2.5 **و** الزيادة عن المتوقع ≥ 15%.
4. **التوقع**: الشهور القادمة ± 1.96 × الانحراف المعياري للبواقي (نطاق ثقة تقريبي 95%).
5. **جودة النموذج**: Backtest على آخر 3 شهور (يظهر لما تتوفر 18 شهر فأكثر).

> ملاحظة: لو أدخلت قراءات يومية وكان آخر شهر ناقصًا (مثلًا 10 أيام فقط)، سيظهر استهلاكه أقل من الحقيقي. الأفضل إدخال شهور كاملة.

## التشغيل المحلي
```bash
python -m venv .venv && source .venv/bin/activate    # على ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
python generate_sample.py        # اختياري: يولّد sample_data.csv
python app.py                    # http://localhost:5000  (SQLite افتراضيًا)
```
ثم من الصفحة اضغط **تحميل بيانات تجريبية** أو ارفع ملف CSV بصيغة:
```csv
date,kwh
2025-01-01,310.5
2025-02-01,295.0
```

## التشغيل بـ MySQL
باستخدام Docker (الأسهل):
```bash
docker compose up --build       # http://localhost:8000
```
أو على قاعدة MySQL موجودة عبر متغير البيئة:
```bash
export DATABASE_URL="mysql+pymysql://USER:PASSWORD@HOST:3306/energy"
python app.py
```
الجداول (`readings`, `alerts`) تُنشأ تلقائيًا عند أول تشغيل.

## تنبيه البريد الإلكتروني (اختياري)
عيّن المتغيرات: `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_USER`, `SMTP_PASSWORD`, `ALERT_EMAIL_TO`. يُرسل بريد مرة واحدة عند اكتشاف شهر شاذ جديد.

## النشر السحابي (Cloud Deployment)
المشروع جاهز كـ Docker image (`Dockerfile`) ويقرأ المنفذ من `$PORT`، فيصلح لأي منصة حاويات:
1. ارفع الكود إلى GitHub.
2. أنشئ قاعدة MySQL مُدارة (مثل AWS RDS أو Google Cloud SQL أو Railway).
3. انشر الحاوية على خدمة مثل Google Cloud Run أو AWS App Runner أو Railway أو Render.
4. عيّن `DATABASE_URL` (ويُفضّل حفظه كـ secret وليس في الكود) ثم افتح رابط الخدمة.

نقطة `/health` متاحة لفحص الجاهزية. ملف `Procfile` موجود للمنصات التي تعتمد عليه.
